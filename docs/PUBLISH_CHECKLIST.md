# 公開確認手順

## 自動確認

リポジトリのルートで、公開用ファイルを作ってから同じファイルを検査します。

```sh
npm test
npm run prepare:pages
E2E_ROOT=_site npm run test:e2e
E2E_ROOT=_site npm run test:e2e:webkit
```

`npm test` は麻雀ロジック、教材、問題、点数計算、保存状態、静的な公開資産、アクセシビリティの契約を確認します。ブラウザ検査は次を含みます。

- 名前入力を含むホーム、メニュー、教材、問題、点数計算、対局練習、学習記録、設定の主要経路
- 名前を切り替えたときに教材の完了進捗と問題記録が混ざらないこと
- 麻雀用語・役名が、表示中の本文でカタカナのルビを上に持つこと
- 問題集の牌姿が横スワイプなしで表示されること
- 「本文へ移動」で画面ID・表示内容を保ち、`main#app`へフォーカスとスクロールを移すこと
- 不正な画面IDと壊れた保存データからホームへ復旧すること
- 初期データと教材データの通信失敗後に、画面内の「もう一度読み込む」で一度だけ再取得できること
- 再試行の連打で同じデータの読み込みが重複しないこと
- 表ドラ、裏ドラ、槓ドラ、槓裏ドラ、自分の河の入力欄を読み上げ名で特定できること
- ヘッダーを含む主要操作の操作領域、320・375・390・402・430pxでのページ全体の横スクロール
- JavaScript例外がなく、faviconとPages配布に必要な静的ファイルが存在すること

## GitHub Actions

- Pull Requestでは `Validate mahjong logic / validate` が `.github/actions/release-checks` を使って検査します。
- `main`への反映後は `Deploy GitHub Pages` が同じ検査をもう一度行います。
- 両方とも `scripts/prepare-pages.mjs` で作った `_site` を検査し、その `_site` をPagesへアップロードします。
- 検査コードは `tests/e2e-smoke.js` を共有し、`E2E_ROOT`だけで検査対象を切り替えます。

公開直前に、`npm test`、Chromium、WebKitのすべてが成功してからPagesの成果物をアップロードします。Pull Request検査と公開前検査は役割が異なるため、同じmain反映で公開前検査を省略しません。

## GitHub Pages確認

1. `Deploy GitHub Pages` の最新実行で、検査とデプロイが成功していることを確認する。
2. 公開URLをSafariのプライベートブラウズで開く。
3. ホームで名前を入力し、メニューから「学ぶ」「問題集」「対局練習」「調べる・記録する」を開く。
4. 初期通信が `manifest`・`rules` に限られ、用語データと教材本文は画面単位で読み込まれることを確認する。
5. 用語の上にカタカナのルビが表示され、問題集の牌姿を横スワイプなしで確認できることを見る。
6. 教材、問題、用語集、点数計算、対局練習、学習記録、設定を開く。
7. 「本文へ移動」、再読み込み、faviconの404、画面全体の横スクロールを確認する。

PlaywrightのWebKit成功は、iPhone Safari実機の確認とは別に記録します。

## iPhone Safari（実機）

iPhone 17 ProのSafariで、次を実際に操作します。

- ホーム、入門1-4、入門1-5
- ホームで名前を入力し、メニューから各入口へ進めること。別の名前へ切り替えて記録が混ざらないこと
- 問題を1問回答し、学習記録へ反映されること
- 点数計算で牌追加、牌削除、計算、全部消すを使うこと
- ツモと捨て牌、鳴き、リーチ、フリテン、案内付き一局、通し型実戦練習、模擬東風戦を最後まで進めること
- 設定変更後の再読み込みと、最後に開いたページの復元
- 縦画面、横画面、文字拡大、キーボード表示中の操作、VoiceOver
- どの主要画面でも「本文へ移動」を押し、画面が変わらず本文へ移ること

この一覧をChatGPT Workだけで確認した場合は実機確認済みとは記録しません。実機で未確認の間は、判定を「自動検査完了・実機確認待ち」とします。

不具合があれば、端末、iOS・Safariのバージョン、URL、再現手順、画面幅、VoiceOverや文字拡大の有無を記録してから修正します。
